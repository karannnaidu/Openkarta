# OpenKarta Protocol — v0.1

**Status:** Initial public release.
**Wire format:** HTTP + JSON. UTF-8 throughout. All money values are integer **minor units** (e.g. paise, cents).
**Date format:** ISO-8601 with offset for absolute timestamps; `YYYY-MM-DD` for date-only fields.
**Currency codes:** ISO-4217 (3 letters).
**Country codes:** ISO-3166 alpha-2 (2 letters).
**Airport codes:** IATA alpha-3 (3 letters).
**Carrier codes:** IATA alpha-2 (2 letters).

This document is the normative reference. Where this document and the Zod schemas in [`packages/spec/src`](../../packages/spec/src) disagree, the schemas win.

## Transport tiers

A merchant declares one tier in their `CapabilitiesManifest.tier`:

| Tier   | Surface                                                                           | When to choose it                                                                          |
| ------ | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `lite` | A static markdown table OpenKarta hosts on the merchant's behalf. Read-only.       | Smallest catalogues, no engineering capacity. No checkout — leads only.                    |
| `http` | The eight verbs in this document, served over HTTPS.                              | Default. Most merchants. Stateful only across the lifetime of an `orderId`.                |
| `mcp`  | Model Context Protocol surface (WebSocket-based stateful tool surface).            | Conversational catalogues, agent-to-agent negotiation, multi-turn search refinement.       |
| `feed` | The merchant publishes a periodic JSON feed; OpenKarta indexes it for search.      | High-volume static catalogues that don't change at runtime.                                |

Conformance is defined per-tier. The conformance harness reads `tier` from the manifest and selects the appropriate test pack. This document specifies the `http` tier — `mcp` and `feed` will be specified in subsequent revisions.

## Authentication & user-token delegation

Calls between consumer agent and brand agent are typically anonymous: discover/search/get/quote do not require any credentials. Checkout-class operations may require the consumer agent to attach a delegation token from the user.

### `x-openkarta-user-token` header

When a user has authorised a consumer agent to act on their behalf, the consumer agent attaches a JWT in the `x-openkarta-user-token` header on `quote`, `checkout`, `status`, `cancel`, and `return` requests:

```
x-openkarta-user-token: eyJhbGciOiJSUzI1NiIs…
```

The token payload follows the schema in [`packages/spec/src/auth.ts`](../../packages/spec/src/auth.ts):

| Field    | Type                          | Description                                                          |
| -------- | ----------------------------- | -------------------------------------------------------------------- |
| `sub`    | string                        | Subject — identifies the user                                        |
| `aud`    | string                        | Audience — the brand agent's `agentId`                               |
| `iss`    | string                        | Issuer — the consumer agent's identity                               |
| `iat`    | int (epoch seconds)           | Issued-at                                                            |
| `exp`    | int (epoch seconds)           | Expiry                                                               |
| `scopes` | array of action names         | Subset of `discover/search/get/quote/checkout/status/cancel/return`  |

The brand agent MUST verify:
- Signature against the registry-resolved consumer agent pubkey.
- `aud` matches its own `agentId`.
- `iat <= now < exp`.
- The requested action is in `scopes`.

If verification fails, the agent returns `unauthorized` (401) or `forbidden` (403).

When no user token is required (e.g. anonymous browsing), the header is omitted.

## Errors

Every non-2xx response has the same shape, defined in [`packages/spec/src/errors.ts`](../../packages/spec/src/errors.ts):

```jsonc
{
  "error": {
    "code":      "quote_expired",
    "message":   "Quote token issued at 12:00:00 expired at 12:10:00",
    "retryable": true,
    "details":   { "expiresAt": "…" }    // optional, free-form
  },
  "requestId": "req_abc123"               // optional
}
```

`code` is drawn from a closed enum. The HTTP status is determined by the code:

| Code                       | HTTP | Retryable | Meaning                                                          |
| -------------------------- | ---- | --------- | ---------------------------------------------------------------- |
| `validation_failed`        | 400  | no        | Request body fails schema validation                             |
| `unsupported_item_type`    | 400  | no        | The agent does not support this `itemType`                       |
| `unsupported_action`       | 400  | no        | The agent does not implement this verb                           |
| `unauthorized`             | 401  | no        | Missing or invalid user token                                    |
| `payment_declined`         | 402  | no        | Payment rail rejected the auth                                   |
| `payment_required`         | 402  | no        | Payment is required to proceed                                   |
| `forbidden`                | 403  | no        | User lacks the requested scope                                   |
| `item_not_found`           | 404  | no        | `itemId` or `orderId` does not exist                             |
| `inventory_unavailable`    | 409  | yes       | Stock dropped to zero between quote and checkout                 |
| `slot_unavailable`         | 409  | yes       | Time slot was just taken (stays / services / flights)            |
| `idempotency_conflict`     | 409  | no        | Same idempotency key reused with a different body                |
| `quote_expired`            | 410  | yes       | The signed quote token's `expiresAt` is in the past              |
| `cart_must_be_homogeneous` | 422  | no        | Cart contains lines of mixed `itemType`                          |
| `quote_invalid`            | 422  | no        | Quote token signature invalid or malformed                       |
| `rate_limited`             | 429  | yes       | Too many requests; retry after `Retry-After` seconds             |
| `internal`                 | 500  | yes       | Unhandled server error                                           |

Implementations MAY add `details` for diagnostics; consumers MUST NOT switch on `details` content.

## Cache control

| Endpoint              | Recommended `Cache-Control`           | Notes                                                  |
| --------------------- | ------------------------------------- | ------------------------------------------------------ |
| `GET /v0/discover`    | `public, max-age=300`                 | Manifests are stable for minutes; the SDK sets this.   |
| `POST /v0/search`     | `private, no-store` (default)         | Inventory may change; do not share across users.       |
| `GET /v0/items/:id`   | `public, max-age=60`                  | Item metadata changes slowly.                          |
| `POST /v0/quote`      | `private, no-store`                   | Quotes are personalised + time-limited.                |
| `POST /v0/checkout`   | `private, no-store`                   | Mutations.                                             |
| `GET …/status`        | `private, max-age=5`                  | Frequently-polled; small TTL avoids stampedes.         |
| `POST …/cancel`       | `private, no-store`                   | Mutations.                                             |
| `POST …/return`       | `private, no-store`                   | Mutations.                                             |

The `@openkarta/sdk-node` server only sets `Cache-Control` automatically on `discover`. Implementations MAY tighten or loosen these values per their inventory volatility (`static / hourly / realtime`).

## The 8 actions

### 1. `discover` — `GET /v0/discover`

Returns the merchant's `CapabilitiesManifest`. No request body.

**Response 200:** [`CapabilitiesManifest`](#capabilities-manifest).

**Errors:** `internal`.

---

### 2. `search` — `POST /v0/search`

Discriminated query keyed by `type`.

**Request body:**

```jsonc
{ "query": <SearchQuery> }
```

`SearchQuery` is a discriminated union over `type`:

#### Product query

| Field          | Type                                 | Required | Notes                                                   |
| -------------- | ------------------------------------ | -------- | ------------------------------------------------------- |
| `type`         | literal `"product"`                  | yes      |                                                         |
| `q`            | string                               | no       | Free-text search                                        |
| `categories`   | array of string                      | no       |                                                         |
| `priceRange`   | `{ minMinor, maxMinor }`             | no       |                                                         |
| `deliverTo`    | `Region`                             | no       |                                                         |
| `deliveryMode` | `instant`/`same_day`/`scheduled`/`pickup`/`standard` | no |                                                  |

#### Stay query

| Field          | Type                                          | Required |
| -------------- | --------------------------------------------- | -------- |
| `type`         | literal `"stay"`                              | yes      |
| `location`     | `Region`                                      | yes      |
| `checkIn`      | string (date)                                 | yes      |
| `checkOut`     | string (date)                                 | yes      |
| `guests`       | int positive                                  | yes      |
| `propertyType` | `hotel`/`homestay`/`apartment`/`villa`/`hostel` | no     |

#### Flight query

| Field         | Type                  | Required |
| ------------- | --------------------- | -------- |
| `type`        | literal `"flight"`    | yes      |
| `origin`      | IATA-3                | yes      |
| `destination` | IATA-3                | yes      |
| `departure`   | string (date)         | yes      |
| `return`      | string (date)         | no       |
| `pax`         | int positive          | yes      |
| `fareClass`   | enum (4)              | no       |
| `nonstop`     | boolean               | no       |

#### Bus query

| Field         | Type                | Required |
| ------------- | ------------------- | -------- |
| `type`        | literal `"bus"`     | yes      |
| `origin`      | string              | yes      |
| `destination` | string              | yes      |
| `departure`   | string (date)       | yes      |
| `pax`         | int positive        | yes      |
| `seatClass`   | enum (5)            | no       |

#### Service query

| Field           | Type                   | Required |
| --------------- | ---------------------- | -------- |
| `type`          | literal `"service"`    | yes      |
| `category`      | string                 | yes      |
| `location`      | `Region`               | yes      |
| `preferredSlot` | string                 | no       |

**Response 200:** `{ "items": Item[] }` — array of the matching item type.

**Errors:** `validation_failed`, `unsupported_item_type`, `rate_limited`, `internal`.

---

### 3. `get` — `GET /v0/items/:itemId`

Single-item lookup.

**Response 200:** an [`Item`](#the-5-item-types) of one of the five types.
**Errors:** `item_not_found`, `internal`.

---

### 4. `quote` — `POST /v0/quote`

Price a homogeneous cart. Returns a signed quote token that the consumer must echo back on checkout.

**Request body:**

```jsonc
{
  "cart":        <Cart>,
  "userContext": { /* optional, free-form (delivery address, fare class preferences, etc.) */ }
}
```

**Response 200:** [`Quote`](#cart-quote-order-refund).

The quote MUST contain a `quoteToken`. The token is HMAC-SHA-256 over `{ cartId, totalMinor, currency, expiresAt }` using a shared secret known to the agent. Consumers MUST treat the token as opaque.

**Errors:** `cart_must_be_homogeneous`, `validation_failed`, `unsupported_item_type`, `inventory_unavailable`, `slot_unavailable`, `rate_limited`, `internal`.

---

### 5. `checkout` — `POST /v0/checkout`

Place an order against a previously-issued quote.

**Request body:**

```jsonc
{
  "cart":       <Cart>,
  "payment":    { "rail": "razorpay_routes", "method": "upi" },
  "address":    <Address>,        // optional; required for delivered goods
  "quoteToken": "<token from quote>"
}
```

**Response 200:** [`Order`](#cart-quote-order-refund).

Side effects: the agent MUST authorise (or capture) the payment rail before returning.

**Errors:** `quote_expired`, `quote_invalid`, `payment_declined`, `payment_required`, `inventory_unavailable`, `slot_unavailable`, `idempotency_conflict`, `internal`.

---

### 6. `status` — `GET /v0/orders/:orderId/status`

Read order + fulfilment state.

**Response 200:** [`Order`](#cart-quote-order-refund).
**Errors:** `item_not_found`, `unauthorized`, `internal`.

---

### 7. `cancel` — `POST /v0/orders/:orderId/cancel`

Cancel an order.

**Request body:** `{ "reason": "user_cancelled" }` (free string).

**Response 200:** updated [`Order`](#cart-quote-order-refund) with `fulfilmentStatus.state = "cancelled"`.
**Errors:** `item_not_found`, `forbidden`, `internal`.

---

### 8. `return` — `POST /v0/orders/:orderId/return`

Initiate a refund.

**Request body:** `{ "items": [...], "reason": "damaged" }`.

**Response 200:** [`Refund`](#cart-quote-order-refund) — refund record with `status: "initiated"`.
**Errors:** `item_not_found`, `forbidden`, `internal`.

## Cart, Quote, Order, Refund

### `Cart`

| Field    | Type                | Required |
| -------- | ------------------- | -------- |
| `cartId` | string              | yes      |
| `lines`  | array of `CartLine` | yes (≥1) |

A cart is **homogeneous**: every line in `lines` MUST share the same `itemType`. The schema enforces this via a `.refine()` that returns the message `cart_must_be_homogeneous: …` when violated. The SDK server maps this into the closed-enum error `cart_must_be_homogeneous`.

`CartLine` is a discriminated union; per-type fields:

| `itemType` | Required fields beyond `itemType, itemId`                            |
| ---------- | -------------------------------------------------------------------- |
| `product`  | `quantity`, optional `variantSku`                                    |
| `stay`     | `checkIn`, `checkOut`, `guests`, optional `specialRequests`          |
| `flight`   | `passengers[]`, optional `seatSelection[]`, optional `addBaggage[]`  |
| `bus`      | `passengers[]`, `boardingPointId`, `droppingPointId`, optional `seatSelection[]` |
| `service`  | `slotStart` (ISO-8601), `slotEnd` (ISO-8601), `headcount` (default 1), optional `notes` |

`PassengerPayload`: `{ firstName, lastName, dob?, gender? (M/F/X), nationality?, idNumber? }`.

### `Quote`

| Field                   | Type                                                  | Required |
| ----------------------- | ----------------------------------------------------- | -------- |
| `quoteToken`            | string (opaque, HMAC-signed)                          | yes      |
| `cartId`                | string                                                | yes      |
| `itemType`              | one of the 5 types                                    | yes      |
| `lineItems`             | array of `{ itemId, description, quantity, unitMinor, totalMinor }` | yes (≥1) |
| `fees`                  | array of `{ label, amountMinor }`                     | no       |
| `taxes`                 | array of `{ label, rate?, amountMinor }`              | no       |
| `discounts`             | array of `{ label, amountMinor }`                     | no       |
| `totalMinor`            | int (non-negative)                                    | yes      |
| `currency`              | ISO-4217                                              | yes      |
| `paymentOptions`        | array of `{ rail, methods[] }` (≥1)                   | yes      |
| `expiresAt`             | ISO-8601 datetime                                     | yes      |
| `estimatedFulfilmentAt` | ISO-8601 datetime                                     | no       |
| `cancellationPolicy`    | `flexible`/`moderate`/`strict`/`non-refundable`       | no       |

Payment rails: `razorpay_routes`/`stripe_connect`/`upi_direct`/`cod`.
Methods: `upi`/`card`/`netbanking`/`wallet`/`cod`/`apple_pay`/`google_pay`.

### Quote token (HMAC envelope)

The reference SDK signs `{ cartId, totalMinor, currency, expiresAt }` with HMAC-SHA-256 over `base64url(JSON)` and concatenates `body.signature`. See [`packages/sdk-node/src/quote-token.ts`](../../packages/sdk-node/src/quote-token.ts). On `checkout`:
- if signature mismatches → `quote_invalid` (422)
- if `expiresAt < now`     → `quote_expired` (410)

## Capabilities manifest

Returned from `GET /v0/discover`. Schema in [`packages/spec/src/manifest.ts`](../../packages/spec/src/manifest.ts).

| Field                 | Type                                                                          | Required |
| --------------------- | ----------------------------------------------------------------------------- | -------- |
| `agentId`             | string                                                                        | yes      |
| `displayName`         | string                                                                        | yes      |
| `protocolVersion`     | literal `"0.1"`                                                               | yes      |
| `tier`                | `http`/`mcp`/`feed`/`lite`                                                    | yes      |
| `baseUrl`             | URL                                                                           | yes      |
| `actions`             | subset of the 8 verb names (≥1)                                               | yes      |
| `supportedItemTypes`  | subset of the 5 item types (≥1)                                               | yes      |
| `paymentRails`        | subset of `razorpay_routes`/`stripe_connect`/`upi_direct`/`cod` (≥1)          | yes      |
| `languages`           | array of BCP-47 tags (≥1)                                                     | yes      |
| `regions`             | array of `Region` (≥1)                                                        | yes      |
| `inventoryVolatility` | `static`/`hourly`/`realtime`                                                  | yes      |
| `catalogSize`         | `small`/`medium`/`large`                                                      | yes      |
| `priceRange`          | `{ minMinor, maxMinor, currency }`                                            | yes      |
| `productCapabilities` | per-type capability bundle, present iff `product` ∈ `supportedItemTypes`      | conditional |
| `stayCapabilities`    | per-type capability bundle, present iff `stay` ∈ `supportedItemTypes`         | conditional |
| `flightCapabilities`  | per-type capability bundle, present iff `flight` ∈ `supportedItemTypes`       | conditional |
| `busCapabilities`     | per-type capability bundle, present iff `bus` ∈ `supportedItemTypes`          | conditional |
| `serviceCapabilities` | per-type capability bundle, present iff `service` ∈ `supportedItemTypes`      | conditional |

Per-type capability bundles (selection):

- **Product:** `categories[]`, `serviceAreas[]`, `deliveryModes[]` (`instant`/`same_day`/`scheduled`/`pickup`/`standard`), `returnWindow` (days).
- **Stay:** `locations[]`, `propertyTypes[]`, `priceTierPerNight: { minMinor, maxMinor, currency }`.
- **Flight:** `carriers[]` (IATA-2), `routes` (`"global"` or array of `{ origin, destination }`), `fareClasses[]`.
- **Bus:** `operators[]`, `regions[]`, `seatClasses[]`.
- **Service:** `serviceCategories[]`, `serviceAreas[]`, `locationModes[]` (`at_customer`/`at_provider`/`online`/`venue`).

A consumer agent SHOULD use the manifest to:
1. Skip search calls with item types that aren't in `supportedItemTypes` (would otherwise return `unsupported_item_type`).
2. Pre-filter based on `regions` / `paymentRails` to avoid wasted round-trips.
3. Pick a polling cadence that respects `inventoryVolatility` (e.g. don't poll a `static` agent every second).

The conformance harness uses `supportedItemTypes` to decide which test packs to run — see `runAll` in [`packages/conformance-tests/src/runner.ts`](../../packages/conformance-tests/src/runner.ts).
